## What changed, by finding

**M12 (High) — a BGZF cut at a block boundary passed every presence check.** Reproduced again with bcftools 1.19: a region BED whose second block and EOF marker are gone passes `gzip -t`, indexes with tabix, and `bcftools view -R` on it exits 0 having dropped every variant on the later contigs (the new `test_bgzf_publish.sh` prints this reproduction when bcftools is available). `scripts/lib.sh` gains `bgzf_complete` (28-byte EOF-marker check) and `publish_bgzf <plain> <final> [preset]` (bgzip to a sibling temp name, require the marker, index, then rename — the final name never holds a partial file; the plain input is consumed, nothing is left on failure). `build_coding_bed.sh` rebuilds a present-but-marker-less BED, refuses to publish a BED missing any contig in `region.required_contigs` (new config key; default `1..22 X Y MT`), and publishes atomically. `run_annotation.sh` refuses to start on a built BED without the marker, without an index, or lacking a required contig (rebuilding a marker-less one with `--force`), and refuses a marker-less custom BED. `download_references.sh` removes and re-installs a marker-less GRCh38 or hg19 FASTA, publishes both through `publish_bgzf`, and writes the chain through a verified temp file (`gzip -t` plus a `^chain ` record). Documented in `docs/ANNOTATIONS.md`. Tests: `test/test_bgzf_publish.sh` (hand-built BGZF blocks — complete, cut, marker-less; real `publish_bgzf` success and a bgzip that drops its EOF block; guard wiring), and `test/test_region_logic.py` rewritten with a BGZF-shaped fake bgzip plus three new cases (missing contig not published, incomplete output not published, incomplete published BED rebuilt).

**M16 — VEP wrote straight onto the deliverable.** VEP now writes `<output>.run<pid>.vep-tmp.vcf.gz` beside the deliverable; `validate_vep_output.py` runs on that file, and only then is it promoted (`mv`) to `$OUTPUT`, with the `_summary.html`/`_warnings.txt` sidecars renamed alongside. The `.deliverable` sidecar is now removed at promotion rather than before VEP, so a run that is killed or fails validation leaves the previous result *and* its pointer intact; the temp file is on the exit-cleanup list. The runner logs `VEP writing to <path>` and `job_progress.py` follows that path for the live variant counter (paths with spaces included). Tests: `test/test_vep_output_promotion.py` (drives the real runner up to VEP with a stand-in `docker` that answers the file-access probe and plays a VEP whose output has no CSQ header: exit non-zero, previous deliverable byte-identical, sidecar present, no temp files — fails on the old runner, which overwrote the deliverable) and `test_counter_follows_the_announced_temporary_vep_output`.

**M13 — liftover working copies and Haplosaurus candidates left behind.** `liftover_grch37_to_grch38.sh` lists every whole-callset working copy (`-supported`, `-source-sorted`, `-split`, `-plugin`, `-normalized-unsorted`, the MT passthrough lane, `-combined-unsorted`, `-all`, `-retained`, `-reference-corrections.raw`, the header) in `LIFTOVER_WORK_FILES` and removes them from an EXIT trap armed after the cache-reuse exit and before the first is written; kept beside the lifted VCF: `-rejected`, `-unsupported`, `-reference-corrections`, QC/provenance and the two small stage-statistics JSONs. In the runner the Haplosaurus `.haplo.selected/candidates/*.id/raw.json` files are registered for exit cleanup so a failed or optional-skipped pass cannot leave look-alike VCFs. Test: `test_liftover_working_copies_are_removed_on_every_exit` (list membership, trap ordering, and the function executed against touched files).

**M19 — a stale liftover lock blocked runs for an hour.** The `mkdir` lock records its holder's pid; a lock whose holder is gone, or whose pid now belongs to a process that is not `run_annotation.sh`, is reclaimed; a live holder is waited for; a pid-less lock from an older version is honoured while fresh and reclaimed after six hours; release only removes a lock the process itself holds. Test: `test/test_liftover_lock.sh` (dead holder, reused pid, live holder honoured then reclaimed once it exits, fresh vs old pid-less lock — through the GRCh37 dry-run path).

**M11 — `shasum ... 2>/dev/null | cut` silently produced "unknown" stamps.** `lib.sh` gains `sha256_file` (shasum → sha256sum → python3, loud failure) and `write_sha256_sidecar`. The ClinVar and catalog stamps in the runner now `die` if the hash cannot be computed (the `:-unknown` fallbacks are gone), `download_references.sh` writes the cCRE/hg19/chain sidecars through the helper, and `verify_container_stack.sh` uses it. Test: `test/test_sha256_helper.sh` (each backend alone on a restricted PATH, no backend at all, sidecar format, and the stamping sites).

**M14 — `bcftools sort` spilled into the container overlay / macOS scratch.** Every sort passes `-T <scratch>/` (the runner's `.guide-iei-work.*` directory; a new `.liftover-work.*` directory in the liftover script, removed with the working copies). `hts()` now preserves a trailing slash on directory arguments so the container sees `-T /hts_N/` and spills inside the bind mount. Test: the trailing-slash case in `test_hts_helper.sh`.

**M15 — containers could reach the network.** `--network=none` on every docker/podman `run` of an offline tool: VEP and Haplosaurus in the runner, `hts()` (both attempts), the catalog builders, `preflight.sh`, `verify_container_stack.sh`, the cohort store's HTS backend, and the bigBedToBed wrapper (singularity has no such flag). Test: `test_hts_helper.sh` asserts the flag in the captured argv and scans every run site.

**M17 — the UCSC `bigBedToBed` download was executed before it was hashed.** `screen_ccre_dataset.py` verifies the download against UCSC's published `md5sum.txt` for the platform directory (or an explicit sha256 pin: `IEI_BIGBEDTOBED_SHA256` / `--bigbedtobed-sha256`) *before* the usage probe runs it; a mismatch deletes the file and refuses; a missing listing fails closed unless pinned; a binary left by an older version (hashed but never verified) is verified in place and replaced if it fails; per-binary manifests record sha256, md5 and what they were verified against. Documented in `docs/SCREEN_TISSUE_IMMUNE_DATA.md`. Tests: four cases in `test_screen_ccre_dataset.py` (the mismatching binary plants a marker if executed — it is not).

**M10 — ClinVar was re-downloaded on every run and any network hiccup failed the run.** `fetch_clinvar.sh` writes `clinvar_latest.<assembly>.vcf.gz.provenance.json` (upstream MD5, release, size) after each publication; before downloading it fetches NCBI's MD5 and, when it matches the installed copy (which must be a complete BGZF with its index), reuses it without a download. When NCBI is unreachable (curl connect/DNS/timeout, as opposed to a 404 for a mirror without checksums) or the download fails, an installed release is reused with a warning instead of `die`; only "no network and nothing installed" is fatal. Documented in `docs/ANNOTATIONS.md`. Test: `test_fetch_clinvar.sh` extended (unchanged upstream → no download; new MD5 → download; offline → reuse with warning; marker-less installed copy → never reused; offline with nothing installed → fails).

**M18 — three full decompression passes before VEP.** The FILTER census awk now also emits the total, so PASS-filtered runs count the input in the same pass; record counts otherwise come from the index (`bcftools index -n`) when one exists, and the post-filter count reads the index just written. Asserted through the runner's log line in `test_vep_output_promotion.py`.
