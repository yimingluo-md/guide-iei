# Maintaining the documentation

The [User Guide](guide.md) is the canonical task-by-task route. Keep README
and desktop/platform entry points short and link to it. Reference pages hold
field contracts and command-line details; avoid duplicating long setup steps.

## Checks before a release

From the repository root, using the environment prepared by setup:

```bash
python3 scripts/check_documentation.py
python3 test/test_documentation.py
node webui/scripts/export-glossary.mjs --check
```

The clean-clone workflow runs these checks. The Python checker verifies local
inline Markdown links and heading anchors, Bash-fence syntax without executing
commands, restricted direct-dataset URL patterns, and the generated predictor
table. It does not verify external website availability, full Markdown/Jekyll
rendering, PowerShell syntax, or whether prose matches runtime behavior.
External links and documented workflows still need manual review.

After a registry or glossary change, regenerate rather than hand-editing:

```bash
python3 scripts/check_documentation.py --write-generated
node webui/scripts/export-glossary.mjs
```

The [predictor table](PREDICTOR_REFERENCE.md) derives from
`config/predictor-registry.json`; glossary definitions derive from
`webui/app/glossary-data.ts`. Registry defaults are not necessarily UI defaults:
installed-state rules and per-run settings must be checked in the application.

## Screenshot refresh

Use only invented demo data generated by `scripts/make_demo_vcf.py`, never
patient files or licensed source rows. The screenshot helper requires a
separate UI, service, storage registry, and empty reference tree:

```bash
bash scripts/capture_manual_screenshots.sh
```

It needs installed WebUI dependencies and Chrome (set `IEI_CHROME` if needed).
It starts on ports 3017/43127 by default; `IEI_MANUAL_UI_PORT` and
`IEI_MANUAL_SERVICE_PORT` can select other unused ports. It leaves generated
images and logs in the printed temporary workspace for inspection, then stops
its processes. Review each image before copying it to `docs/assets/img`.
The helper must not run against an active user workbench, trigger annotation
or dataset downloads, or rely on blurring patient names after capture.

Check dataset labels/grouping and installed-state controls, frequency presets,
FuncVEP CTI-only default, clinical-evidence columns, and current button labels.
Explain when a screenshot shows an unconfigured demo workstation. A screenshot
is a UI illustration, not a biological validation result. The coverage report
image is generated from the same synthetic VCF by the wrapper.

## Manual acceptance checklist

- Follow clean Mac release, Mac source ZIP, Windows launcher, and direct WSL
  startup paths. Verify security guidance without recommending protection bypasses.
- Follow both UI and direct-command annotation on a tiny valid synthetic VCF;
  confirm malformed input produces the documented error.
- Check dataset setup against installer behavior: bulk membership, required vs
  optional, user acknowledgement/files, labels, preparation space, and retry.
- Exercise retained import, Review once, duplicate/reannotated import, phenotype
  mapping, Cohort Search, and backing up/reopening a copied library.
- Verify annotation/intake/review filter scope and missing-score behavior.
- Run the public installed-resource regression panel and report optional skips;
  do not describe dry-run or unit tests as proof of full biological coverage.
- Preview the hosted manual, check image readability and chapter navigation,
  and test external source links. Use repository web links for source code
  outside `docs/`, because those files are not published by the docs site.
- Scan screenshots, logs, and examples for private paths, patient identifiers,
  registration links, credentials, and copyrighted source rows. Retain RUO
  language unless a separately approved policy change calls for revising it.
